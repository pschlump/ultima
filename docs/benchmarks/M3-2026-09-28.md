# M3 Pub/Sub Benchmark Report — 2026-09-28

Milestone M3 exit criterion: redis-benchmark pub/sub (design doc §14.4).

## Environment

- Machine: Apple M4 Max, 14 cores, 36 GB RAM (darwin/arm64)
- Ultima: `ultima-server v0.0.2-dirty (commit 9524ccb62b0c907a4355cd19a9657afae25496a1, branch main, built 2026-09-28T20:03:27Z for darwin/arm64)` (shards: 4×GOMAXPROCS, power of two)
- Redis: `Redis server v=7.2.7 sha=00000000:0 malloc=libc bits=64 build=7f24f11dd7e42c58` (via REDIS_BIN=redis-server; `--save '' --appendonly no`)
- Driver: `redis-benchmark 7.2.7`, PUBLISH benchchan payload, -n 300000 per run (-n 100000 for -c 1)
- Subscribers: 8 × `note/pubsub-bench-sub` (Go discard-and-count reader;
  redis-cli formats every message and cannot drain fast enough, which trips
  Ultima's slow-consumer close — a client artifact, so it was not used)
- Ultima config: `{"server":{"resp_addr":"127.0.0.1:7379","log_level":"error"}}`

Numbers are single-run means from redis-benchmark's summary output;
rerun `make bench` for a fresh sample. Both servers ran on the same
loopback interface, sequentially, with no other benchmark load.

Delivery check: subscriber connections still attached after the run
(PUBSUB NUMSUB) and per-subscriber received-message counts from the
driver. Since M9c, a subscribed connection's push queue is
byte-capped (lib/pushq, server.pubsub_client_buffer_mb, default
32 MB — Redis's client-output-buffer-limit pubsub hard-limit
default) and the push writer flushes in batches (lib/resp
PushValues), so full publisher speed no longer drops subscribers
on these legs; a connection is closed only when its queued bytes
pass the ceiling (slow consumer), and subscribers that stay
attached receive every message.
