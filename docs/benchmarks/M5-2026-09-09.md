# M5 Maxmemory Soak Report — 2026-09-09

Milestone M5 exit criterion: maxmemory soak (design doc §14.4,
docs/m5-detailed-plan.md M5d).

## Environment

- Machine: Apple M4 Max, 14 cores, 36 GB RAM (darwin/arm64)
- Ultima: `ultima-server dc5a24c-dirty (commit dc5a24c6b2422d9a8bea6cd9376e3b34ba2ec4ef, branch master, built 2026-09-09T15:27:24Z for darwin/arm64)` (shards: 4×GOMAXPROCS, power of two; eviction quota per shard = maxmemory/shardCount)
- Redis: `Redis server v=7.2.7 sha=00000000:0 malloc=libc bits=64 build=7f24f11dd7e42c58` (via REDIS_BIN=redis-server; `--save '' --appendonly no`)
- Driver: `redis-benchmark 7.2.7`
- Soak: maxmemory 64 MB, `SET key:__rand_int__ <1024-byte value>`
  over a 1000000-key random space (`-r`, ~20x what fits), -c 50 -P 16,
  -n 2000000 per run; volatile-* policies add `PX 600000` so keys are
  evictable
- Ultima config: `{"server":{"resp_addr":"127.0.0.1:7379","log_level":"error"},"persist":{"save":""\}}`,
  `maxmemory`/`maxmemory-policy` set live via CONFIG per run

Numbers are single-run means from redis-benchmark's summary output;
rerun `make bench-m5` for a fresh sample. Both servers ran on the same
loopback interface, sequentially, with no other benchmark load.

used MB is INFO `used_memory` after the run; "evicted" is the
`evicted_keys` delta over the run. The two used_memory columns are not
comparable to each other: Ultima reports the keyspace estimate the
maxmemory gate enforces (bounded by construction, D10), Redis reports
process memory including allocator overhead, so Redis rows legitimately
sit above the 64 MB limit. The Ultima check column is the soak
assertion: used_memory within 5% of maxmemory, evicted_keys advancing
under the evicting policies, and a post-run probe SET returning Redis's
byte-exact OOM error under noeviction vs OK under the evicting policies
(noeviction rps is n/a: once full, every write is rejected and
redis-benchmark prints no throughput summary for an all-error run).
