# M6 detailed plan — Auth system, HTTP management API, Web UI v1

Design doc §14.4 M6: "Auth system (§9) + HTTP API + web UI v1". Exit
criteria: **login/refresh/TOTP green; multi-admin accounts; WS recovery tests
pass; dashboard + console live**.

Relevant settled decisions: D7/D11 (OpenAPI contract-first, wired chi-server
bindings), D16 (JWT access + refresh tokens with rotation), D17 (multiple
admin accounts on the account base; TOTP via `pschlump/htotp`), D18
(resumable WS sessions), D20 (Ed25519/EdDSA JWT signing, key pair from config
file paths, both required, no auto-generation). Do not reverse these.

Execution is phased M6a → M6d, each phase independently green
(`go test ./...`, `make lint`).

**Status: M6a done. M6b–M6d not started.**

---

## M6a — Auth core — **done**

Accounts, Ed25519 JWTs, TOTP 2FA, and auth enforcement on all three gated
surfaces. HTTP routes are hand-wired chi closures in `lib/handler/auth.go`
(existing repo style); M6c migrates them under the oapi-codegen contract when
the full API surface lands.

- `auth` config group (`lib/config`): `enabled` (default off — off preserves
  every pre-M6 behavior), `jwt_private_key_file` / `jwt_public_key_file`
  (Ed25519 PKCS#8 / PKIX PEM, generated by `bin/gen-jwt-keys.sh`),
  `access_token_ttl`, `refresh_token_ttl`, `totp_issuer`, `totp_skew`,
  `accounts_file` (default `<persist.dir>/accounts.json`),
  `bootstrap_admin_password` (`$ENV$` capable), `ws_replay_buffer_ms` /
  `ws_replay_buffer_max_msgs` (declared; consumed by M6b).
- `lib/auth`:
  - `keys.go` — key-pair load; both files required, pair match verified,
    startup fails otherwise (D20).
  - `accounts.go` — `Account` (bcrypt pass hash, two-phase TOTP:
    pending secret staged by enable/regenerate, promoted on confirm),
    `RefreshFamily` (single-use rotation, previous-hash theft detection →
    family revoked), JSON store with atomic tmp+rename write-through,
    last-enabled-admin and bootstrap-admin guards, dummy-bcrypt compare for
    unknown users.
  - `tokens.go` — EdDSA access JWT (`sub`/`class`/`jti`/`iat`/`exp`,
    issuer `ultima`) via `golang-jwt/jwt/v5`; verify checks the account
    still exists and is enabled, so delete/disable kills outstanding
    access tokens immediately.
  - `service.go` — login / refresh-rotation / logout / password change
    (revokes sessions) / TOTP enable-confirm-regenerate-disable (htotp;
    enrollment response carries secret + otpauth:// URI + QR PNG via the
    new `htotp.GenerateQRCodePNG`) / admin CRUD. First boot creates the
    bootstrap `admin` account (§9.1) from `bootstrap_admin_password` or a
    generated password logged exactly once; startup warns while `admin`
    is the only enabled admin (§9.5).
  - `middleware.go` — `RequireAuth`/`RequireAdmin` HTTP middleware,
    identity in request context; gRPC unary+stream interceptors
    (`authorization: bearer …` metadata → `Unauthenticated`); scheme
    match is case-insensitive.
- Endpoints (`lib/handler/auth.go`): `POST /api/v1/auth/login|refresh`
  (public; 401 `totp_required` when 2FA on), `logout`, `password`,
  `totp/enable|confirm|regenerate|disable` (Bearer),
  `GET|POST /api/v1/admin/users`, `PUT|DELETE /api/v1/admin/users/{name}`,
  `POST .../revoke-sessions` (admin class). `handler.Register` gates all
  other `/api/v1/*` behind `RequireAuth` when auth is on; `/health`,
  `/ready` stay public (§10.1).
- Surface enforcement: gRPC interceptors in `grpcsrv.New(eng, svc)`;
  WebSocket upgrade auth in `wssrv.Handler(eng, svc, logger)` —
  `?access_token=` query param or `Sec-WebSocket-Protocol: bearer,
  <token>` (browsers can't set headers); `ConnState.User` carries the
  account username. RESP `AUTH`/`requirepass` untouched (§10.1).
- Tests: `lib/auth/auth_test.go` (keys, bootstrap, token verify incl.
  foreign-key/expired/deleted-account rejection, rotation + theft,
  TOTP flow incl. regenerate, CRUD guards, reload persistence),
  `tests/m6_test.go` (full HTTP flows, gRPC with/without bearer, WS
  upgrade both token forms, reload at wiring level).
- Deps added: `golang-jwt/jwt/v5`, `golang.org/x/crypto` (bcrypt),
  `pschlump/htotp` via `replace => ../htotp` (like pluto).
- Known follow-ups: no login rate-limiting yet (add with M6c hardening);
  no origin policy on `/ws/v1` (M6d); token TTL strings parsed at startup
  only (no CONFIG SET).

## M6b — WS resumable sessions (§9.4, D18)

- Proto: add `session`/`last_push_seq` handshake fields to
  `Command`/`CommandResponse` (and `push_seq` on push frames); `make
  gen_proto` regenerates Go + TS.
- `lib/wssession`: per-session registry, bounded replay buffer
  (`auth.ws_replay_buffer_ms` / `ws_replay_buffer_max_msgs`), `push_seq`
  stamping at the `ConnState.StartPush` funnel, subscription retention
  across disconnect (defer `CloseConn` within the retention window),
  SESSION_EXPIRED / ABORTED-by-seq frames.
- Tests: reconnect replay (no gap, no duplicates), buffer-window expiry,
  slow-consumer interplay, goleak clean.

## M6c — HTTP management API (§10.1, D7/D11)

- `api/openapi.yaml` as contract source of truth, embedded and served at
  `/api/openapi.yaml` + Swagger UI (`lib/httpapi`); oapi-codegen
  chi-server bindings wired properly; `go-playground/validator/v10` DTO
  validation via the `JsonBody` default-tag helper.
- Migrate M6a auth routes into the contract; add the §10.1 groups:
  `/metrics` (Prometheus, IP-allowlist), `/info`, `/shards`, `/clients`
  (+kill), `/slowlog`, `/latency`, `/config` GET|PUT, `/flushdb`,
  `/save` family (move from lib/handler), `/keys/scan`, `/key/{key}`
  GET/DELETE.
- Middleware chain per §10.1: request-id → logging → real-IP → Recoverer
  → Timeout → Prometheus → JWT (already have logging/Recoverer/JWT; add
  the rest). Preserve the `Unwrap`/`Hijack` contract for `/ws/v1`.

## M6d — Web UI v1 (§10.2)

- `web/` React + TypeScript + vite, bun-managed; `web/dist` embedded via
  `//go:embed`; login screen with TOTP, automatic token refresh.
- Screens: dashboard, key browser, live monitor (WS), slowlog, config
  editor, pub/sub inspector, account administration with QR enrollment.
- Interactive console over `/ws/v1` with push-mode rendering and session
  recovery (needs M6b).
