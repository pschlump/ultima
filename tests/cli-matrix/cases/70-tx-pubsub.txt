# Transactions + pub/sub-group cases: MULTI, EXEC, DISCARD, WATCH, UNWATCH,
# PUBLISH, PUBSUB (empty-state only).
#
# Streaming verbs (SUBSCRIBE/PSUBSCRIBE/UNSUBSCRIBE/PUNSUBSCRIBE/MONITOR) are
# banned from case inputs — the CLIs stream forever on them; live delivery is
# covered by the runner specials (special:pubsub-delivery etc.). EXEC-nil on a
# watched-key change is not testable on a single connection, so it is skipped
# by design. All expected strings probed against redis-server 7.2.7; RESP3
# renders every reply shape used here identically to RESP2 (verified with
# redis-cli -3), so no == resp3 blocks are needed.

# Regression: EXEC arity error comes in EXECABORT form and discards the tx
== case: tx-pubsub.exec-extra-args
# Divergence: EXEC with wrong arity (extra argument) and NO MULTI active.
#   real Redis 7.2.7: (error) EXECABORT Transaction discarded because of:
#                     wrong number of arguments for 'exec' command
#   ultima:           (error) ERR wrong number of arguments for 'exec' command
# Redis wraps the EXEC arity failure in its EXECABORT form (probed on a live
# 7.2.7 server, RESP2 and RESP3, with and without requirepass; standalone
# connection, no MULTI in effect). Ultima replies with the plain arity error.
EXEC extra
--
(error) EXECABORT Transaction discarded because of: wrong number of arguments for 'exec' command
== end
