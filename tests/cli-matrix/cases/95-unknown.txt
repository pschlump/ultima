# Unknown-group cases: byte-exact 'unknown command' errors for Redis 7.2.7
# commands that ultima deliberately does NOT implement (functions, string
# range/bit ops, keyspace move/copy/dump, SORT, OBJECT,
# LCS, streams, geo, HyperLogLog, ACL, replication, cluster, introspection
# containers like LATENCY/MEMORY/MODULE/SLOWLOG).
#
# Every case except unknown.sync/unknown.psync is '== targets: no-redis': a
# real redis-server implements most of these and would NOT error, so the
# expectations would fail validation.
#
# Error shape (matches Redis 7.2.7):
#   ERR unknown command '<name>', with args beginning with: '<a1>', '<a2>',
# Name as typed (case preserved); each arg single-quoted with a trailing
# space; zero-arg commands end the line right after "with: " (trailing
# space — the trailing spaces on the expected lines below are significant).
#
# redis-cli client-side quirks worked around here (redis-cli.c, 7.2.7):
#   * 'sync'/'psync' put redis-cli into slave output mode (it prints
#     "SYNC with master failed: -ERR ..." + "Entering replica output
#     mode..."), so those two cases are '== targets: resp3,no-redis'
#     (ultima-ws-cli and ultima-grpc-cli render the error normally; the
#     real-redis validation targets skip them because a real redis would
#     answer SYNC with an RDB dump stream).
#   * redis-cli prints the reply RAW (no "(error) " prefix) for 'lolwut'
#     (any arity), 'memory doctor'/'memory malloc-stats', 'cluster info'/
#     'cluster nodes' (2-arg), 'latency doctor' (2-arg)/'latency graph'
#     (3-arg) and 'debug htstats*' — so unknown.lolwut uses 'match' with an
#     optional "(error) " prefix and the memory/cluster/latency/debug cases
#     simply use other subcommands.
