
# Support Libraries

There will need to be a TypeScript library and a JavaScript library
for clients that are going to access the HTTP and WebSocket interface
from a client.

Examples of using this with full user interfaces will need to be
built as a part of the documentation for the library.  How about a
game leader board that has real time updates.   Come up with some
others decent examples.

# Login extensions

The HTTP login facility will sit on top of the existing Redis Clone
user security.  The login facility will need to add a TOTP 2-Factor
key as an option for login authentication.  There will need to be
administrative accounts instead of just a single built in admin
account.    The builtin account shall be able to create additional
administrative accounts with usernames, passwords and 2fa keys.
This will sit on the current user and ALC system inside Redis-Clone
(Ultima) now.  This will need to cover users for both WebSockets
and gRPC.   For WebSockets as an upgrade to HTTPs this will use a
standard JWT authenticated token system with refresh tokens and
authentication tokens.   Because of the likelihood of the WebSocket
connection being an unreliable connection a connection will need
to have a connection recovery system so that a client that looses
its connection can recover the connection without loss of messages.

There will need to be facilities for change of password for 
accounts.

# Web front end

The web front end should have an interactive window that just allows
you to run Ultima commands, and returns with the results in a second
area at the bottom of the screen. It is essentially the same as the
CLI but as a web front end.  This should also work for things that
result in content being pushed from the server like SUBSCRIBE /
PSUBSCRIBE.
